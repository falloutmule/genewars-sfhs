# Save and replay formats

The normal campaign uses `kind: "genewars-campaign-save"`, `schemaVersion: 2`, and engine `0.2.0-campaign-development`. The envelope contains the complete implemented `world`, a `session` and a checksum of both. Loading checks the content pack hash, engine/schema, checksum, native pool shapes, logical bindings, spatial registry and command state. Campaign JSON input is limited to16MB. Unknown versions are refused; no earlier campaign release exists to migrate. The separate version1 workbench saves remain development harness saves and cannot become campaign starts. No DOS-save compatibility is claimed.

Campaign state includes the monotonic replay tick and native mission frame; RNG seed, ring and draw count; source mission prefix and numeric pool priors; players and complete blueprint records; specialists, orders, construction projections and terrain jobs; native buildings, economy, power packets and production; terrain, plants, creature records and owned Mule queues; shared200-slot effect records, landing/water hosts and spatial links; countdown, all16 Ethereals, objective/result state, pending commands and entry carry/restart recipe. Native process pointers are null or logical references, never serialized addresses. The implementation remains incomplete: fields and tests do not establish unimplemented combat, AI or later mission acceptance.

Construction and crater work share the serialized25×176 source terrain pool and its actual count. Each working construction projection carries `nativeSlot`; load checks unique active slot bindings and matching duration. Earlier unreleased development snapshots with active normalized terrain jobs and no native slot are refused. Completed jobs need no invented native allocation or lossy migration.

Session state contains pause, speed (`0.5`, `1`, `2`, `4`) and fractional clock accumulator. Browser camera, selection, renderer objects, input capture and audio-device state are outside the world. Simulation audio requests are inside the world because their ordering is deterministic. Rendering and playback consume state without changing gameplay.

FNV-1a over canonical UTF-8 JSON detects accidental corruption and simulation drift; it is not authentication. SHA-256 identifies the imported pack. JSON serialization does not preserve shared object identity: the host explicitly synchronizes specialist/construction motion, so resumed travel does not depend on in-memory aliases.

The normal UI stores three manual slots and four rotating recovery slots in IndexedDB database `genewars-campaign`, store `saves`. Recovery rotation is one read/write transaction, preserving older slots if a write aborts. Compatible legacy localStorage slots are read as a fallback. Export/import supports file-origin use when browser storage is unavailable. Clearing browser storage deletes local slots; exporting a JSON save creates an independent copy.

Recovery points include deployment, periodic active callbacks, result actions, menu exit, `pagehide` and visibility backgrounding. Manual load pauses the restored world and starts a replay segment at that full snapshot. Save/reload tests cover implemented travel, construction, result stages and carried entry; additional active subsystem boundaries must be tested as they are implemented.

Campaign replay schema2 records source commit and dirty status (null when unknown), pack hash, a full initial world, initial RNG, ordered events by monotonic tick, periodic full-world checksums and a final tick/checksum/result/carry hash. Events include briefing entry, player commands, result actions and campaign continuation. Native mission frame resets at transition; replay tick does not. Commands issued while paused at the final tick are replayed. The initial RNG and timeline are validated; rejected/unreachable events, periodic drift and final result/carry drift fail. A failed replay world is exposed only for isolated diagnostics and is never installed as a successful session.

Workbench replay version1 remains separate. Both formats require explicit migration or a clear incompatibility message when their authoritative contracts change; never silently discard gameplay state to load a save.

# Exceland power and GOOP mechanics

`src/sim/mechanics/economy.ts` independently expresses the recovered observable economy. `stepEconomy(state, context, rules)` returns a proposed immutable after-state, ordered events, per-building reasons and enabled-consumer timer samples, or an atomic reason-bearing failure. All numeric rates, ranges, caps, cadence thresholds, storage amounts and grade animation holds are required `EconomyRules` inputs with an evidence identifier. There is no fallback profile and no original fixture or proprietary animation table in this module or its tests.

The source evidence is the preserved `genewars/genewars-preflight` archive, specifically:

- `research/integration/mission-001-acceptance-004.json`: later ordinary/native Exceland acceptance and carried Krell entry. This supersedes the early mission-001 note's historical acceptance count; it does not accept this TypeScript implementation.
- `research/variants/building-power.md`, `rust/crates/genewars-runtime/src/building_power.rs` and `actor_world/power_buildings.rs`: source451F0 producer prefix, distinct Distributor/Photon target filters, signed generation/storage, frame phases, per-recipient ranges, splitting and effect33 requests; separate postphysics4C8E6 delivery/byte decay and caps.
- `research/campaign/mission-001-contract.md`, `rust/crates/genewars-runtime/src/extractor_production.rs` and `actor_world/extractor_updates.rs`: energy/cycle/animation gates, first strictly richest wrapped neighborhood cell, grade harvest quantity, capped credit, exhaustion and terrain/contact obligations. The reviewed full callback/animation evidence admits grade0; higher grades require independently admitted hold tables. Empty hold arrays explicitly reject those callbacks.
- `rust/crates/genewars-runtime/src/building_progress.rs::recompute_player_capacity`: source43620 storage and operational HQ aggregation. Occupied storage contributes before completion unless source suppression flags exclude it; depletion flags disable the Extractor without removing its capacity.
- `rust/crates/genewars-runtime/src/bookkeeping.rs`: source47F80 enabled completed non-generator timer samples and bounded437A0 Extractor allocation, unallocated positive-resource disposal, warning trigger/cooldown and countdown behavior.

The numeric-profile mapping is direct: mission global11A9BF supplies `context.solarGeneration`; source producer coefficients/caps/phases/ranges supply `rules.power`; source Extractor upkeep/cycle/harvest coefficients supply `rules.extractor`; imported per-grade BMINE running-animation holds supply `frameHolds`; source43620 supply coefficients and437A0 warning constants supply `rules.capacity`. The adapter must decode complete, disabled, capacity suppression0x840 and HQ suppression0x140 independently. Energy is a signed16 counter, packets retain unsigned-byte payload behavior, and secondary resources retain signed storage/allocation plus unsigned harvest comparisons.

`tools/import-original/economy_profile.py::import_economy_rules(decoded_bmine, executable_sha256=verified_hash, source_version=SOURCE_VERSION)` builds that profile for the audited CD variant. The caller must first verify the executable bytes; this adapter validates its supplied identity/version, then independently validates decoded BMINE's full length/SHA-256/section geometry and admitted grade0 animation. It reads each hold from the actual frame metadata byte, with no palette or sprite decode requirement. Grade1/2 arrays remain empty and are explicitly listed as unsupported. Its provenance distinguishes independently expressed source constants/formulas from the one actual binary-derived field, `extractor.frameHolds[0]`. Returned rules and binary-derived values belong in the ignored private pack. Importer tests use invented metadata/hold bytes and scope a test-only expected-digest replacement to exercise the successful admission path; no public original fixture is included and the production API has no digest override.

The Extractor credits the secondary resource at player+4A7. Construction pays the distinct primary resource at+4A3. This module never turns extraction into construction income. Photon processing produces **power**, using the mission solar input plus grade; the reviewed Exceland evidence establishes no separate GOOP refinery conversion.

The source-order host calls `stepEconomyBuildings` for47F80, followed later by `stepEconomyPackets` during4E950 effects. Building generation/consumption/harvesting/player timers never run inside the packet phase; packet delivery/decay never runs inside the building phase. Packet observations dispatch in supplied host source-slot order, including after stable slot reuse. `targetValid:false` represents the source destination-kind clear after target destruction and forces lifetime decay even if a building ID/slot is reused. The historical `stepEconomy` convenience function retains its delivery-first composition for compatibility; campaign code must use the two explicit phases. Distributor creation does not immediately credit its targets. Missing packet observations preserve a packet without invented travel or decay. `generatedEnergy` is the normalized per-step total rather than an opaque native player field after its scheduler tail. Timer samples are ordinary count/mean/min/max outputs rather than a reproduction of the original history ring/sentinels.

`power-motion.ts` expresses effect33's reusable horizontal factory/motion family: speed2048/pitch512, launch-vector trig tables, constant signed XY velocities, eight retained fractional bits,15-bit toroidal integration, postphysics terrain+512 delivery height, four-frame animation and signed timer. It introduces no homing or RNG. Its shared200-slot pool preserves actual inactive fraction bytes and occupancy of nonpower effects; first-free allocation and retirement/reuse keep stable source indices. Missing fraction priors and full-pool priority replacement reject atomically. Initial source packed-effect bytes59/60 map to native67/68 and supply actual fractions, rather than assumed zero allocation memory. Target destruction clears the logical destination kind; payload0→255 and1→0 lifetime behavior stays in the packet economy phase.

`campaign/power-adapter.ts` connects those plans to the shared spatial pool. It initializes from actual packed effect records, synchronizes landing/particle occupancy and fractions, launches ordered building requests, applies packet movement/relinking, delivers/decays, and retires slots/links in source slot order. It stages mutations so allocation or late delivery failure does not partially commit. The host must retain references to particle objects before `stepLanding` filters them, then pass removed objects to `synchronizePowerAdapter` after unlinking; the final moved fractions otherwise disappear at retirement. `createExtractorContactSmoke` replaces a four-draw-only placeholder with the real three contact draws plus one code6 animation-delay factory draw, actual shared allocation/fraction priors and a spatially linked particle. Full-pool priority replacement and the complete global mixed-effect scheduler remain explicit boundaries.

`advancePowerProducerRng` runs in native building order, interleaved with Extractor contact callbacks, before numerical economy commit. Every Distributor/Photon pulse consumes one shared draw **even when no target exists**. It predicts signed generation, transient drain, saturation and the source pulse condition; source target selection/factories follow without additional draws. Direction derives from the old animation frame before a random frame1 kick. Photon sets delay3, requests stop23 at idle and uses the source play condition/range; Distributor uses its source modulo7 play condition. Serializable `building.producer` holds the actual animation/action, requested audio state, latest requests and callback identity. Running holds come from actual BPOWE/BSOLA action1 metadata. Grade0 animation admission is enforced; missing or other-grade profiles reject. Actual audio playback remains a host service. New grade0 completion animation priors follow source42FA0/43F60 and construction-counter clamping; a missing prior with nonzero running frame0 hold rejects.

`planExtractorContactQueries` walks the actual shared contact cell and returns ordered foreign8B000 then own8B080 candidates, preserving source link/alliance order and the source virtual68 state>=24 exclusion. A live result requires the actual virtual34 callback even for grade0 incoming damage0. The archived Extractor world adapter rejects such occupied live contacts, and existing bounded Mule damage adapters exclude incoming0 and Extractor attacker-kind4; no no-op equivalence has been established. The host must resolve those side effects or stop that callback explicitly. Unknown owner/state bytes remain an error. Empty/dead/allied-excluded results can establish the bounded no-damage contact path.

Every powered harvest frame requires its ordered host contact pass to appear in `contactResolvedBuildingIds`. This indicates that required contact/damage/particle work has actually been resolved; it is not a bypass for unknown actor damage. `terrain-depleted` requires the host's source terrain cleanup/retessellation, and `extractor-empty` requires the host's presentation/notification handling. A receipt is a proposed transaction: the caller must complete these obligations before committing it. Work audio cues are requests; playback state remains explicit input. Local-player selection determines which player notices are presented.

Generic consumers are visible as delivery targets and timer samples but return `host-consumer-callback-required` for their specialized behavior. This module does not execute Genepod production, combat or other selectors' resource use. Capacity contributions for store selectors4/13 are recovered, but their allocation body has not been established here: positive GOOP with those stores returns `additional-storage-allocation-required` atomically. Selector12's conditional special delivery effects likewise return a failure. Other campaign warning/countdown effects and mission result logic remain separate.

`tests/economy.test.ts` uses a deliberately different synthetic profile and synthetic resource grids. It exercises grade-dependent production, distinct eligibility/ranges, storage saturation/empty targets, packet delivery/decay/seams, no immediate recipient credit, signed arithmetic, cycle/animation timing, capacity/full/empty resource behavior, depletion requests, power loss/restoration, ordered storage allocation, discard notices, deterministic output and atomic unsupported boundaries. Passing it establishes these contracts, not canonical mission acceptance or original frame parity.

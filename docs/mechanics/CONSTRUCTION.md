# Construction stage adapter

`src/sim/mechanics/construction.ts` independently expresses the ordinary category0 construction path for selectors0,1,3,6,11. Rule arrays and animation profiles are caller supplied from the admitted private pack. Synthetic tests exercise the complete lifecycle; this module is not campaign acceptance or a comparison against a live original process.

The stage sequence preserves actual travel before site setup, initial74E80 discriminator100, source reservation and perimeter-height target, a bounded25-job terraform pool, two shared RNG draws on terrain completion, approach movement before payment, signed two-pool debit, action14's actual animation completion gate, code2C building/effect admission, initial progress1, repeated signed skill*2 contributions after110-skill timers, parity-dependent work RNG, randomized work points, final departure and task cleanup. The module has no fixed construction duration. Health and other numeric tables are inputs; no original table contents are embedded.

`beginConstruction(state, actorId, selector, point, rules, context)` applies the placement command's alignment and two target resolutions and creates a task. `stepConstruction` runs one enabled actor callback. `stepConstructionTerrainJobs` runs the separate terrain family once per frame. The host supplies the actual family/selected-actor ordering, increments `state.frame`, and must preserve that order when sharing RNG with other families. Duplicate actor/job-family dispatch within one frame rejects.

Every function returns `{state, events}` and leaves its input untouched. The host must commit the returned state and ordered events together. External audio, viewport refresh, effect animation/link creation, completed-building creature-target cleanup and economy capacity refresh are explicit events. A completion receipt contains `clearCreatureTargets:true` and `refreshCapacity:true`; dropping either request does not produce a complete host integration. `allocateBuilding` is a pure capacity/admission query for48790(code2C), returning the building identity/owner slot and the matching effect slot, or null to retry. The host must materialize the effect and intrusive links with the receipt. It must not execute external side effects inside query callbacks.

Required context binds actual gravity/climate, motion collision admission, source8B340 mask0 occupancy,74A50 target resolution, a declared routing policy, the resource-selected refill flag, effect allocation, and actor animation profiles. `resolveTarget` is the placement command's mask0 search. `resolveTaskTarget` binds6FEC0/74A50 working-target repair with mask1, plant weight<10 and the actual terrain mask. It repairs `task.goal` while preserving `task.requestedGoal` and the construction site. The completed departure is the construction path that nominates its building reference; incomplete work movement must not invent that exemption. Rejected random work points are repaired, not made traversable through plants. Routing can use the existing `findRoute` as an explicit modern reliability policy; its returned destination must equal the repaired goal. Original contour navigation is not established by selecting that policy. The movement/terrain arithmetic is delegated to existing `motion.ts`/`terrain.ts`; this module does not upgrade their own fidelity claims. In particular their omitted shading/transitive effects remain host integration obligations, not proof from construction tests.

`context.animation(actor, id)` returns `{holds,flags}` for the actual animation in that actor's bound resource key. `holds` contains each source frame byte+10; `flags` is animation trailing-word high byte. Calls include directional0..7, idle8 and actions13,14,15. Actor animation state is `{id,frame,hold,direction,delay,counter}`. The byte-counter advance preserves signed delay/counter comparisons and unsigned frame holds. Stage4 tests the previous animation state before advancing the tail. Ping-pong requires frame0/hold0; looping animation requires its final frame/hold0/counter0. There is no elapsed-time substitute.

`cancelConstruction` stops an active terraform job and releases reservation flags only before stage5, matching ordinary51E80. In the campaign, stage1/2 cancellation writes the actual referenced job's remaining word to−1 and decrements the shared count. A job already retired by79220 is not retired twice; this conversion guard prevents a count underflow when a modern paused command arrives before the actor observes completion. It uses `terrain.releaseSite` to preserve vertices still protected by neighboring footprints. Stage5 cancellation leaves its incomplete/completed building and footprint in place and gives no invented refund. Insufficient post-arrival funds use the same cancellation path. The cancelled actor remains serializable and consumes the original journal21B draw on its next recovery callback, then hands ordinary idle behavior back to the host. Destroying buildings, explicit refunds, restoration of raw native opaque fields, ordinary idle neighborhood scoring, class3 charging, other architect task modes, selector5's second site and other building selectors are outside this bounded adapter and reject where entered.

All task phases, routes, animation bytes, timer state, terrain jobs, funds, counts and RNG are plain JSON data. Public tests use synthetic maps/tables/ANB profiles and compare JSON reload continuation in every encountered phase. They also cover real travel, all five selectors, BL100/mineral distinction, action14 gates/null allocation, work RNG, cancellation, actual-fund failure, signed debit edge cases, duplicate scheduling, invalid references and late-error rollback.

Campaign construction now uses source791C0/77B80's actual25×176 retained terrain pool, shared with craters. The constructor writes only its rectangle, dimensions, step, targets and duration in the lowest inactive slot; full capacity performs no writes or RNG. The campaign dispatches one ascending79220 pass for all jobs, including ordered linked heights, material/shade work and zone refresh. Construction jobs store their native slot and mirror the resulting duration; the separate `stepConstructionTerrainJobs` helper remains an isolated mechanic harness and refuses a campaign native image. Earlier development saves containing active normalized jobs without a native slot are explicitly incompatible.

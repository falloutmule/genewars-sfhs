# Specialist native pool and factory

`specialist-native.ts` provides serializable20-slot family2 storage, source57540 loading, source81310 allocation, source4FD30 construction, source80830 no-associated-unit placement and source56E20 resource binding. The original executable is never run or embedded. Host bootstrap/world files are not modified by this module.

`loadSpecialistPool(packed,priors,options)` accepts20*140 source bytes and20 explicit nullable200-byte priors. The optional default `unknownSpecialistPriors()` means unknown bytes, not zero bytes. For each slot, it copies packed[0,31) to native[0,31) and packed[31,140) to native[39,148). Native[31,39) and[148,200) remain caller priors/null. It never reads beyond a slot into the next source record. Inactive slots do not run an initializer or clear their runtime tail. Active source records require actual retained player records and original resource/style tables, check their identity/owner partition, and run the exact56E20 numeric clear/binding. This is distinct from the generic native-stride-minus-eight loader, whose copy shape is unsuitable for200/140 specialists.

Native process-address ranges31..39,176..180 and192..200 are always null. Unknown nonpointer numeric bytes also remain null until a proven write establishes them. Required reads reject unknown values. `SpecialistBinding` separately records the owner/blueprint handle, style/category, original source resource name and asset key, flat key4*style+category, original class speed, animation slot31, blueprint slot192, resource slot196, internal176→196 and logical kind3 class. Resource binding admits signed source style/category0..3 and uses the imported sixteen resource descriptors. It does not substitute Human art for another style or assign category2 an arbitrary resource.

`createSpecialist(pool,playerRaw,request,rules)` stages a complete pool and player afterimage. It finds the first inactive slot in the owner's five-slot partition, preserves unused link indices, appends the actual global ID5*owner+local through player byte3, and ORs the actual blueprint runtime flag20 with1. A full native partition produces no allocation and no player mutation. A free native slot with a full five-ID list rejects rather than overrunning source storage. Invalid later initialization also leaves both caller inputs unchanged.

`projectSpecialistMotion` exposes the actual native coordinates, physical/ground height, width, fractions, velocity, acceleration, angles, speed and desired speed, with the original class speed separately named. Class speed is not written into a native desired-speed field that the factory leaves untouched. The projection does not invent steering flags or convert unknown numeric fields to defaults.

Blueprint generation, retained-player restoration and choosing the mission mask remain caller responsibilities.

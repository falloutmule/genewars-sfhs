# Deterministic runtime staging

The simulation keeps its existing atomic callback boundaries. A successful
callback commits its complete mutable host; a late failure discards that stage.
Nested source services run inside the same stage and retain native/player array
identities, allowing recursive damage and factories to observe current state.

Profiling the converted runtime identified repeated generic copies as the main
local cost. Specialized copies now cover spatial heads/nodes, economy resource
arrays and nested producers/extractors, shared effect slots/native priors,
specialist records/retained bindings and campaign actors/builders/players/audio.
The actor/builder copier preserves existing motion and other shared aliases by
identity. It does not invent aliases from equal values. Optional generic host
roots retain their structuredClone default.

Ordinary Mule relocation uses the same complete mutable host copier as the
shared effect scheduler, avoiding copies of immutable imported mission input.
All native families potentially touched by recursive factories, jobs, collapse,
presentation and cleanup are still isolated. Held creature records, terrain and
RNG are the actual callback stage, rebound before commit.

Synthetic tests mutate nested leaves, exercise staged spatial movement and
verify sibling/original isolation, retained inactive bindings, alias graphs and
late-failure rollback. Private frozen-runtime comparisons run both versions on
identical ordinary Exceland and actually carried Krell inputs. Complete states
are deeply equal through Exceland400 and Krell450, including undefined own
properties. Local Node windows improve from20.82 to8.87ms/tick and30.59 to12.36ms/tick;
concurrent load and JIT effects limit those timings. They establish neither
browser performance nor physical-phone acceptance. Rules, RNG and fixed tick
rate are unchanged. Canonical acceptance remains0/24.
